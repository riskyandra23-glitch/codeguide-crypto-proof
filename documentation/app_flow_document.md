# codeguide-crypto-proof App Flow Document

## Onboarding and Sign-In/Sign-Up
A new user first arrives at the public landing page, which briefly explains the Crypto Wallet Aggregation and Proof-of-Funds service and invites them to get started. The page features a clear call to action labeled “Sign Up” and “Sign In.” When the user clicks “Sign Up,” they are taken to Clerk’s hosted sign-up form. They can create an account by providing an email and password or by using a social login option such as Google or GitHub. Once they complete the form, Clerk verifies their email address before allowing full access.

If the user has an existing account, they click “Sign In” on the landing page or in the top navigation. They enter their email and password or choose a social provider. After successful authentication, Clerk sets a secure session cookie and redirects the user to the main dashboard. If the user forgets their password, a “Forgot Password” link on the sign-in form opens a reset flow powered by Clerk. They enter their email, receive a reset link, choose a new password, and return to the sign-in screen. Signing out is available in every dashboard header menu under “Log Out,” which clears their session and returns them to the landing page.

## Main Dashboard or Home Page
After signing in, the user lands on the dashboard overview. The layout includes a left-hand navigation bar with links labeled “Wallet,” “Payments,” “Proofs,” and “Settings.” The top header displays the user’s name and a profile avatar, and offers the “Log Out” option. In the center of the screen, three widget cards show a summary of connected wallets, current subscription status, and recent proof-of-funds requests. A primary action button in the wallet widget invites the user to “Connect Wallet.” From here, clicking any navigation link smoothly loads the corresponding page without refreshing the browser.

## Detailed Feature Flows and Page Transitions
When the user clicks “Wallet” in the sidebar, they arrive at the wallet connection page. The page displays a prompt to connect a wallet using the WalletConnector component. Clicking “Connect Wallet” opens a modal powered by Web3Modal. The user chooses a wallet provider such as MetaMask or WalletConnect and approves the connection. Once connected, the page automatically calls the `/api/balances` endpoint via React Query. A loading spinner appears until the balances for Ethereum, BSC, and Polygon are fetched using ethers.js. Then the BalanceDisplay component renders a table of aggregated balances.

Below the balance display, the PaymentButton component becomes enabled. When clicked, it calls the `/api/checkout-session` endpoint to create a Stripe Checkout session. The user is redirected to Stripe’s hosted payment page, where they enter their card details. After successful payment, Stripe sends a webhook to `/api/webhooks/stripe`, which updates the user’s paid status in Supabase. Upon returning to the application, the user lands on a success page at `/success`. This page confirms payment and presents a “Generate Proof” button. Clicking it calls `/api/generate-proof`, passing the user’s ID and aggregated balances. The backend generates a PDF with pdfkit, embeds a QR code that links to `/verify/[token]`, stores a record in the `proof_requests` table, and streams the PDF back to the user for download.

To verify a proof, a third party scans the QR code and is taken to a public verification page at `/verify/<token>`. The page calls `/api/verify/[token]`, retrieves the proof metadata, and displays the transaction date, balances, and user identifier. If the token is invalid or expired, the page shows a clear error message and a link to the home page.

## Settings and Account Management
In the “Settings” section, the user can update their profile information such as display name and email. Clerk’s widget handles these updates and confirms changes instantly. A separate tab under Settings labeled “Billing” shows the current subscription or one-time payment status. Here the user can view past invoices, update their payment method, or manage recurring subscriptions directly through an embedded Stripe Customer Portal link. Changes in billing status immediately reflect on the dashboard and gate access to proof generation if payment is not current. A “Back to Dashboard” link at the top of Settings returns the user to the main overview.

## Error States and Alternate Paths
If the user enters an invalid wallet address or the JSON-RPC call fails, the BalanceDisplay component shows an error banner reading “Unable to fetch balances. Please try again.” The “Retry” button invokes the React Query refetch. During payment creation, if Stripe returns an error, the Checkout flow redirects back with an error message and suggests retrying or contacting support. In the PDF generation step, server errors produce a friendly message: “We’re sorry, something went wrong creating your document. Please try again later.” On the verification page, invalid or already-used tokens display “This proof is not valid or has expired,” with a link back to the landing page. Network interruptions anywhere show a full-page notice stating “Connection lost. Attempting to reconnect,” and automatically retry once connectivity is restored.

## Conclusion and Overall App Journey
From the moment a user arrives at the codeguide-crypto-proof landing page, they are guided through a straightforward sign-up or sign-in process powered by Clerk. After authenticating, they land on a dashboard that summarizes their wallet connections, payment status, and proof history. In the wallet section, they connect their wallets, view aggregated balances, and then proceed to pay via Stripe. Upon successful payment, they generate a proof-of-funds PDF with an embedded QR code. Third parties can verify proofs by scanning the code and viewing the data on the public verification page. Throughout this journey, users can manage their profile and billing settings, and any errors or interruptions are met with clear messages and recovery options. This flow ensures a smooth path from wallet connection to secure proof generation and easy verification.
